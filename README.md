# 🤖 Staff Manager Bot

بوت داخلي لإدارة **الدعم الفني** (7 رتب) و**الإشراف** (5 رتب) و**الإدارة العامة للسيرفر** (رتبتان: `General Manager` و`Co General Manager`) في سيرفر ديسكورد واحد.
واجهة عربية بالكامل • Node.js + discord.js v14 • SQLite (بدون أي تكلفة).

> الإدارة العامة فريق مستقل ولا توجد له ترقية تلقائية. التعيين والإزالة لا يتمان إلا بقرار من `Server Manager` أو `General Manager` الحالي.

## ✨ الأنظمة

| النظام | الوصف |
|--------|-------|
| 📚 FAQ | قاعدة معرفة بـ 11 تصنيف + قوالب مستقلة يمكن نشر كل قالب في أي قناة وتعديله وحده، بحث، تأكيد قراءة، سجل إصدارات |
| 📡 النشاط | تتبع تلقائي لكل رسالة مع أوزان القنوات وفلتر السبام وتنبيهات الغياب (72/96 ساعة/7 أيام) |
| 🎫 التكتات | قراءة تلقائية لرسالة إغلاق بوت التكتات من قناة محددة — بدون تكامل API وبدون `/log-ticket` — مع منع التكرار والنقاط التلقائية |
| 🏛️ الإدارة العامة | `General Manager` و`Co General Manager` بصلاحيات إشرافية، وتعيين يدوي محمي من Server Manager/GM فقط |
| 🧾 التدقيق والمهام | Audit Log للعمليات الحساسة + مهام متابعة وتأهيل تلقائية للأعضاء الجدد |
| 💾 النسخ الاحتياطي | نسخة SQLite يومية + `/backup` والاحتفاظ بآخر النسخ |
| 🛡️ مخالفات الإشراف | تسجيل كل إجراء إشرافي مع الدليل |
| 🏖️ الإجازات | 5 أنواع، منع التداخل، موافقة/رفض بأزرار، رتبة `in vacation` تلقائية، حد 30 يوم / 3 مجازين، تذكيرات، إلغاء وإنهاء مبكر، تجميد الاحتساب |
| 📤 الاستقالات | سرية، منع التكرار، سحب قبل الاعتماد، قبول (Boss فقط) / رفض / تعليق، تذكيرات آخر يوم، إزالة الرتب الإدارية و`in vacation` تلقائياً |
| ⚠️ الإنذارات والملاحظات | 6 أنواع بنقاط وتجميد وإيقاف، ملاحظات سرية |
| 📈 Score | درجة 0-100 بمعايير مختلفة لكل فئة (Helper / Support+ / الإشراف) |
| 🎯 الترقيات | شروط كاملة (مدة + Score + نقاط + تكتات/مخالفات + تقييم + إنذارات + تبريد) — لا ترقية تلقائية |
| 📊 التقارير | فردي، فريق، Leaderboard، تقارير يومية/أسبوعية/شهرية تلقائية مع مقارنة |

## 🚀 التشغيل (3 خطوات)

```bash
npm install
cp .env.example .env     # ضع DISCORD_TOKEN و CLIENT_ID و GUILD_ID فقط
npm run deploy && npm start
```

ثم داخل السيرفر اكتب **`/setup`** (يتطلب Administrator) — معالج تفاعلي بقوائم اختيار:

| الخطوة | كيف |
|--------|-----|
| 🎧🛡️🏛️ الرتب (14) | الدعم والإشراف والإدارة العامة مع **مطابقة تلقائية بالاسم** 🪄 أو اختيار يدوي |
| 🏖️ رتبة الحالة | اربط رتبة Discord باسم `in vacation` من زر **رتبة الإجازة**؛ المطابقة التلقائية تبحث عن الاسم، ولا تُمنح صلاحياتاً |
| 📁 القنوات (10) | **إنشاء تلقائي** ✨ ينشئ كاتيجوري `📋 Staff Manager` بالقنوات الداخلية وصلاحياتها الصحيحة |
| 🤖 مصدر التكتات | اختر قناة سجل الإغلاق التي يرسل فيها بوت التكتات رسالته — اختيارية لكنها مطلوبة للتسجيل التلقائي |
| 👑 Server Manager | اربط رتبة المالكين/Server Manager من /setup؛ مالك السيرفر يستطيع دائماً التعيين |
| 📡 قنوات النشاط | اختر قنوات/كاتيجوري التكتات والإدارة والإشراف (اختياري) |

**لا حاجة لنسخ أي معرف (ID).** الإعدادات تُحفظ في قاعدة البيانات وتظهر بشريط تقدم ✅. `config.json` ما زال مدعوماً كمصدر احتياطي اختياري.

### الصلاحيات المطلوبة للبوت في Discord Developer Portal
- Intents: `Server Members`, `Message Content`
- Permissions: إدارة الرتب، إدارة القنوات (للإنشاء التلقائي)، إرسال الرسائل، تضمين الروابط
- **يجب أن تكون رتبة البوت أعلى من كل الرتب الإدارية** — المعالج ينبهك إن لم تكن كذلك

### التسجيل التلقائي للتكتات بدون ربط البوتين
لا يحتاج Staff Manager إلى API أو صلاحيات خاصة من مالك بوت التكتات. بعد اختيار **مصدر سجل التكتات** من `/setup`، يراقب البوت رسائل البوتات في تلك القناة فقط، ويستخرج:

- رقم التكت
- صاحب التكت
- مستلم التذكرة
- من أغلق التكت
- رابط ملف السجل إن وجد

ثم يسجل العملية ويضيف النقاط مرة واحدة حسب `message_id`. ويمكن اختيار `TICKET_LOG_BOT_ID` اختيارياً لتقييد القراءة على بوت محدد. إذا لم تتوفر رسالة سجل صحيحة يبقى `/log-ticket` كخطة احتياطية. التسجيل اليدوي يقتصر على صاحب الأمر؛ المشرفون فأعلى فقط يستطيعون تسجيل تكت باسم إداري آخر، وكل تجاوز يُحفظ في Audit، كما لا يمكن تكرار رقم تكت يدوياً لمنح نقاط إضافية.

### قوالب FAQ المستقلة
لإنشاء لوحات مختلفة:

```text
/faq-template-create
/faq-template-list
/faq-template-send id:1 channel:#قناة-الدعم
/faq-template-edit id:1
```

كل قالب يحفظ عنوانه ووصفه ولونه والتصنيفات التي يعرضها. إذا عدّلت قالباً، تتحدث لوحاته المنشورة المرتبطة به فقط، ولا تتأثر القوالب الأخرى. حذف قالب لا يحذف رسالته؛ يحولها إلى اللوحة الافتراضية.

### دورة الإجازة والاستقالة

- عند اعتماد الإجازة تُمنح رتبة `in vacation` فوراً. إذا لم تكن الرتبة مربوطة أو لم يستطع البوت تعديلها، يسجل التحذير ويُرسل تنبيه للمراجع؛ يمكن إعادة المحاولة تلقائياً من المجدول.
- لا تُزال الرتبة عند نهاية إجازة إذا كانت هناك إجازة معتمدة أخرى نشطة أو قادمة للعضو. وعند عدم وجودها تُزال ويعود العضو إلى الحالة النشطة، مع تنبيه عدم العودة بعد يوم.
- `/cancel-leave` يلغي الطلب المعلّق أو الإجازة القادمة فقط، بينما تستخدم الإدارة `/end-leave` لإنهاء إجازة بدأت بالفعل. كل قرار يسجل في Audit.
- يمنع النظام تداخل طلبات الإجازة المعلّقة أو المعتمدة لنفس العضو، ويتحقق من الحد الأقصى للمجازين عند الاعتماد.
- طلب الاستقالة المعلّق يمنع طلباً مكرراً. يستطيع صاحبه استخدام `/withdraw-resignation` قبل القبول، وتُرسل تذكيرات سرية قبل آخر يوم وعند تجاوزه. عند القبول تُلغى الإجازات المرتبطة وتُزال الرتب الإدارية ورتبة `in vacation`.

## ⏰ المهام التلقائية

| المهمة | التوقيت |
|--------|---------|
| فحص الغياب | كل 30 دقيقة |
| رفع الإيقاف المنتهي تلقائياً (`suspended_until`) | يومياً 01:00 |
| تفعيل/إنهاء الإجازات، مزامنة `in vacation`، وتذكيرات العودة | يومياً 00:05 |
| تذكيرات الاستقالات المعلّقة والقريبة من آخر يوم | يومياً 00:20 |
| نسخة احتياطية لقاعدة البيانات | يومياً 00:15 |
| التقرير اليومي | يومياً 09:00 |
| التقرير الأسبوعي + Leaderboard + نقاط الأسبوع + تقارير فردية بالخاص | الجمعة 10:00 |
| التقرير الشهري + مقارنة + أفضل إداري + تحليل الاستقالات | أول كل شهر 11:00 |
| صيانة البيانات: تجميع النشاط القديم + تقليم السجلات + VACUUM | أول كل شهر 03:00 |

المنطقة الزمنية تُضبط عبر `TZ` في `.env` (الافتراضي `Asia/Riyadh`).

npm run check     # ESLint + الاختبارات + بوابات سجل الأوامر وتحديث README

نفس الخطوات جاهزة كسير عمل GitHub Actions في `docs/ci-workflow.yml`

أي مهمة فشلت أو تجاوزت دورتها تُسجَّل في جدول `job_runs`، ويعرض `/system-status`

### كيف يُحسب Score؟

| السؤال | الجواب |
|--------|--------|
| ما نافذة الاحتساب؟ | الشهر الحالي (والتقارير الأسبوعية على 14 يوماً) |
| رسالة في قناة تكت = رسالة في قناة عامة؟ | لا: للأوزان أثر فعلي (تكتات 50% • إدارة 25% • إشراف 25% • عام 10%) |
| إداري بلا تقييم مشرف؟ | يُستثنى وزنه من المقام ويُوحَّد الباقي إلى 100 — لا نقاط مجانية |
| إداري بلا عمل إطلاقاً؟ | لا يظهر في Leaderboard بل في قسم «غير مصنّف» مع سبب استبعاده |
| من يتصدّر؟ | من لديه ≥ 3 أيام نشاط أو عنصر عمل واحد على الأقل في النافذة |

### الصيانة والاسترجاع

| الأمر | ماذا يفعل |
|-------|-----------|
| `/backup` | نسخة جديدة + **فحص سلامة فوري** (`PRAGMA integrity_check`) — وإن فشل الفحص يُعلن الفشل صراحةً |
| `/backup-list` | النسخ المحفوظة وحجمها وعمرها + فحص أحدث نسخة |
| `/maintenance` | معاينة ثم تنفيذ: تجميع نشاط أقدم من 12 شهراً في `activity_monthly`، تقليم `audit_logs` أقدم من 18 شهراً، ثم `VACUUM` |

- **عصور النقاط**: كل رتبة عصر مستقل (`rank_epoch`)، فتُحسب نقاط الرتبة الحالية وحدها
  ويبقى السجل التاريخي كاملاً — بدل صف سلبي مزيف كان يلوّث التاريخ.
- **تاريخ الرتب**: كل تغيير رتبة يُسجَّل في `staff_rank_history` (من، إلى، من نفّذ، ولماذا)
  ويظهر في `/staff-record` و`/my-record`.
- **تدريب الاسترجاع**: الخطوات كاملة في [`docs/RESTORE.md`](./docs/RESTORE.md) —
  يُنفَّذ مرة كل ثلاثة شهور.

### لماذا لا يوجد خصم تلقائي عند الأداء الضعيف؟

الأسبوع الضعيف (Score أقل من 50) لا يُخصم منه -10 تلقائياً، بل يُدرج في
«قائمة المراجعة البشرية» داخل التقرير الأسبوعي ليقرر المشرف إن كان السبب إجازة،
أو مرضاً، أو انخفاضاً حقيقياً. العضو في فترة التجرية (`probation`) معفى من هذه القائمة.

> **ترحيل اختياري للأيام القديمة:** `npm run migrate:tz -- --dry-run` يعرض نشاط
> السجلات التي كُتب يومها بتوقيت UTC قبل التوحيد ويصحّحها بتوقيت `TZ`.

## 🔌 طريقة قراءة سجل بوت التكتات
التسجيل التلقائي معزول في `services/ticketLogs.js`: لا يوجد ربط بين البوتين. Staff Manager يقرأ رسالة الإغلاق من قناة مخصصة، يحلل الـ Embed/النص، ثم يحفظ `source_message_id` لمنع التكرار. تنسيق الرسالة الحالي يدعم عبارات مثل `صاحب التكت` و`مستلم التذكرة` و`الي قفل التكت` و`رقم التكت` مع منشنات Discord.
